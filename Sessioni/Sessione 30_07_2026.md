## 2. Contratto dati (decisioni D1–D5)

Queste sono le regole su come sono fatte le entità. **Gasparini (DTO) e Scolaro
(schema SQL) devono seguirle entrambi.** Nessuno le cambia da solo: se emerge un
problema, va segnalato nelle domande aperte.

- **D1 — L'utente ha una chiave numerica `id` (int).**
  La tabella `Utenti` ha `id SERIAL PRIMARY KEY`; `username` diventa `UNIQUE NOT NULL`.
  Tutte le chiavi esterne puntano a `id`, non a `username`.

- **D2 — Il ruolo si chiama `RISTORATORE`** (non "GESTORE").
  Enum `Ruolo { CLIENTE, RISTORATORE }`. Lo schema SQL aggiorna il vincolo `CHECK`.

- **D3 — I servizi sono un'entità separata con tabella di collegamento.**
  `ServizioDTO(id, nome)`, tabella `Servizio`, tabella ponte
  `RistoranteServizio(id_ristorante, id_servizio)`. Si elimina il vecchio campo
  `servizi` testuale. `delivery` e `prenotazioneOnline` restano invece booleani sul
  ristorante, perché servono come filtri di ricerca.

- **D4 — La fascia di prezzo è un intero da 1 a 4.**
  Conversione dai simboli del CSV: € = 1, €€ = 2, €€€ = 3, €€€€ = 4.
  DTO: `fasciaPrezzo` int. SQL: `SMALLINT CHECK BETWEEN 1 AND 4`.

- **D5 — Il luogo è diviso in tre campi.**
  `nazione`, `citta`, `indirizzo` separati, sia nel DTO che nello schema. Lo chiede
  DIRETTIVE §2 (ricerca per luogo).

### Definizione delle entità

Per ogni campo: nome, tipo Java (nel DTO) e tipo SQL (nella tabella).

**Utente** — tabella `Utenti`

| Campo | Tipo Java | Tipo SQL | Note |
|-------|-----------|----------|------|
| id | int | SERIAL PRIMARY KEY | D1 |
| username | String | VARCHAR UNIQUE NOT NULL | usato per il login |
| password | String | VARCHAR NOT NULL | salvata come hash SHA-256, mai in chiaro |
| nome | String | VARCHAR NOT NULL | |
| cognome | String | VARCHAR NOT NULL | |
| email | String | VARCHAR UNIQUE | |
| dataNascita | LocalDate | DATE | facoltativo |
| domicilio | String | VARCHAR | facoltativo |
| ruolo | Ruolo | VARCHAR CHECK IN ('CLIENTE','RISTORATORE') | D2 |

**Ristorante** — tabella `RistorantiTheKnife`

| Campo | Tipo Java | Tipo SQL | Note |
|-------|-----------|----------|------|
| id | int | SERIAL PRIMARY KEY | |
| nome | String | VARCHAR NOT NULL | |
| nazione | String | VARCHAR | D5 |
| citta | String | VARCHAR | D5 |
| indirizzo | String | VARCHAR | D5 |
| latitudine | double | DOUBLE PRECISION | |
| longitudine | double | DOUBLE PRECISION | |
| fasciaPrezzo | int | SMALLINT CHECK 1..4 | D4 |
| tipoCucina | String | VARCHAR | |
| delivery | boolean | BOOLEAN | filtro di ricerca |
| prenotazioneOnline | boolean | BOOLEAN | filtro di ricerca |
| telefono | String | VARCHAR | dal CSV, facoltativo |
| sitoWeb | String | VARCHAR | dal CSV, facoltativo |
| premi | String | TEXT | dal CSV, facoltativo |
| idGestore | Integer | INT FK Utenti(id) ON DELETE SET NULL | D1, può essere nullo |
| mediaStelle | double | (nessuna colonna) | calcolato con una query AVG |
| numeroRecensioni | int | (nessuna colonna) | calcolato con una query COUNT |

**Recensione** — tabella `Recensioni`

| Campo | Tipo Java | Tipo SQL | Note |
|-------|-----------|----------|------|
| id | int | SERIAL PRIMARY KEY | |
| idRistorante | int | INT FK RistorantiTheKnife(id) ON DELETE CASCADE | |
| idCliente | int | INT FK Utenti(id) ON DELETE CASCADE | D1 |
| stelle | int | SMALLINT CHECK 1..5 | |
| commento | String | TEXT | |
| data | LocalDateTime | TIMESTAMP DEFAULT now | |
| risposta | String | TEXT | solo il ristoratore, può essere nulla |
| dataRisposta | LocalDateTime | TIMESTAMP | può essere nulla |

Vincolo aggiuntivo: `UNIQUE(id_cliente, id_ristorante)` — una sola recensione per
utente su ogni ristorante.

**Servizio** — tabella `Servizio` + ponte `RistoranteServizio`

| Campo | Tipo Java | Tipo SQL |
|-------|-----------|----------|
| id | int | SERIAL PRIMARY KEY |
| nome | String | VARCHAR UNIQUE NOT NULL |

- Tabella ponte: `RistoranteServizio(id_ristorante INT FK, id_servizio INT FK)`, chiave primaria composta.
- Preferiti: `Preferiti(id_cliente INT FK, id_ristorante INT FK)`, chiave primaria composta.

> **Regola I1.** I DTO contengono solo i campi, i getter/setter e il
> `serialVersionUID`. Nessuna logica di dominio dentro i DTO. Le regole (media
> delle stelle, una recensione per utente, solo il ristoratore può rispondere)
> vanno nei service o nelle query SQL.

mettere in cima a ogni `.java` prima di iniziare a scrivere codice:

rompe la comunicazione tra client e server.
